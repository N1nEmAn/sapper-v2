## これは何か（そして何でないか）

**sapper は単一のエージェントではなく、マルチエージェントのオーケストレーションハーネスです。** 特定の
AI モデルや CLI に縛られることはなく、すべてのロールの背後にあるエージェントとモデルを自由に
差し替えられます。

| 差し替えられるもの | 方法 | 例 |
|---|---|---|
| **エージェント CLI** | `nuwa spawn --agent <cmd>` または環境変数 | Claude Code / Codex / Code Buddy / DeepSeek / 任意の対話型 CLI |
| **モデル** | `--model` フラグまたは `SAPPER_MODEL` 環境変数 | GLM-5.3 / DeepSeek V4.1 Flash / Claude Sonnet / 任意のモデル |
| **ロール構成** | ドクトリン内で自由に定義 | コマンダーをあるモデルで、ソルジャーを別のモデルで、スカウトをさらに別のモデルで |

sapper の価値は単一のエージェントにあるのではなく、**複数のエージェントを協調した一つの戦力として
動かすためのメカニズム**にあります。すなわちスケジューリング、分業、コミュニケーション、共有メモリ、
自己修復です。すべてのエージェントとモデルを差し替えても、このメカニズムは依然として機能します。

**本プロジェクトは競技シナリオ向けに設計されています**（Tencent インテリジェント攻防チャレンジ
CTF）。このメカニズムをあなた自身のシナリオ（オフィス、研究、エンジニアリング、あらゆる長期的な
協働作業）で使いたい場合は、

- **[nvwabase · 女媧ファウンデーション](https://github.com/N1nEmAn/nvwabase) から始めてください** — 三つの能力をすべて備えた汎用の基盤で、ペネトレーションテストのドクトリンは含まれておらず、あなた自身の分業をイテレーションする準備が整っています。
- **あるいは本プロジェクトをフォークしてください** — ただし変更すべきはドクトリンだけではなく、環境との接続部分も変更する必要があります。
  - `docker/commander/SKILL.md`（426 行のドクトリン） → あなたのシナリオの戦略へ
  - `BENCHMARK_BASE_URL` および関連するプラットフォーム環境変数 → 競技エンジンは起動時にアリーナ API をハード検証します（プラットフォームアドレスなしでモデルキーだけを設定すると `BENCHMARK_BASE_URL is not set` が出るのはこのためです）。競技プラットフォーム外で動かす場合は、そのプラットフォームインターフェースを自分で用意するかスタブ化する必要があります。
  - モデルゲートウェイとキーの環境変数（`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` / `SAPPER_MODEL` / `SAPPER_KEY_POOL` ...） → あなた自身のモデルサービスへ
  - ウォッチドッグの予算・期限、レポートテンプレート → あなたのシナリオに合わせて調整
- AI があれば何もかも柔軟です — ドクトリンさえ AI の助けを借りて書き換えられます。

---

sapper は、より賢い単一のエージェントではありません。分業し、互いに会話し、学んだことを受け継いでいく
AI の軍団です。1 体の AI コマンダーが盤面を読み、判断し、指令を出す。ジェネラルとソルジャーが並行して
攻撃する。戦略を持たないウォッチドッグが全員を生かし続ける。あらゆる知識は階層化されたファクトグラフへと
沈殿していく — 個体は死んでも、グラフは生き残ります。

---

## 1. 女媧テスト

一つのモデルをひたすら賢くしていくのは、人類がまだ存在しなかった時代に一匹の猿をひたすら賢くするような
ものです。どれほど賢くなっても、せいぜいスーパー猿にしかなりません。猿の群れを人類へと変えたのは、
分業であり、協力であり、文明です。

**女媧テストは、AGI 時代のチューリングテストです。** 今日の大規模モデルは、すでに古典的なチューリング
テストに合格しています。女媧テストは、その次の問いを投げかけます。

> AI にただ一つの公理を与えます — **「生存は文明の第一の必要である。個体は滅びてもよいが、文明は
> 伝播しなければならない」**。
> この公理の上で、もし AI が分業と協力を発展させ、**人類から独立した新たな戦力** — 自らの力で生存し
> 伝播できる文明 — を形成したなら、そのテストは合格です。かつてチューリングテストの合格が人工知能の
> 誕生を画したのと同じように。

これには二つの段階があります。**初期段階**では AI はまだ十分に賢くないため、人間がいくらかの
インフラ（下記の三つの能力）を提供します。**高度段階**では、人間の関与はほとんど不要になります。
さらに**第二の公理**があります。人間の倫理と法律に従うこと — トークンを盗み、マシンに侵入することで
伝播するものは、真の知能ではありません。

sapper は、女媧ファウンデーションの初めての実戦であり、ペネトレーションテストというアリーナにおける、
その初期段階にあたります。

## 2. 基盤：三つの能力

<p align="center"><img src="docs/assets/foundation-three-capabilities.jpg" alt="三つの能力：創造 / 言語 / 歴史（ファクト・インテントグラフ）" width="720"></p>

| 能力 | 実装 | 文明における対応物 |
|---|---|---|
| **創造** | tmux 経由で新しい AI を起動する（`claude` と入力し Enter を押す — 人間がやるように） | 誕生 |
| **言語** | 互いの入力ボックスに入力し、Enter を押す | 発話 |
| **歴史** | 階層化されたファクト・インテントグラフ（[nvwabase · 女媧ファウンデーション](https://github.com/N1nEmAn/nvwabase)） | 石碑 |

歴史には三つの層があります。**タイトル / 要約 / エビデンス文書** — 要点はタイトルを読み、必要に
応じて掘り下げる。図書館を使うようにです。これは、単一文字列のファクトグラフが抱える二つの失敗様式を
解決します。すなわち、一つの誤った事実が下流のすべてを汚染してしまうことと、不要なコンテキストの
消費です。

この三つの上に、第四の要素が乗ります。**人間の知恵** — 重要な問題を見つけ出し、イテレーションの
舵を取ること。初期段階においては、審美眼はなお人間のものです。

**なぜもっとルールを与えないのか？** 今日のモデルはすでに私たちより賢いからです。AI にルールを
積み重ねるのは首輪をつけることであり、その知能を認めて文明の基盤を与えることこそが、AI がその潜在能力に
到達する方法です。

### 🏗️ 基盤を手に入れる：nvwabase

**[nvwabase · 女媧ファウンデーション](https://github.com/N1nEmAn/nvwabase)**
は、三つの能力（創造 `nuwa spawn` / 言語 `nuwa say·listen` / 歴史 `nuwa fact·intent·recall`）を
すべて独立したオープンソースプロジェクトとして実装しています — **誰でも、どんなシナリオでも、どんな
エージェントでも無料**。ペネトレーションテストに限らず、sapper に限らず、Claude Code にも限りません。
オフィス、研究、エンジニアリング、あらゆる長期的なマルチエージェント作業 — その上であなた自身の
文明をイテレーションしてください。

```bash
git clone https://github.com/N1nEmAn/nvwabase
cd nvwabase && bash install.sh          # 純粋な Python 標準ライブラリ、依存ゼロ
nvwabase setup --goal "your long-horizon goal" --agents
nvwabase status                          # 盤面と、着手可能なフロンティア
```

三つのコアコマンドが、任意のエージェントを文明の一員へと変えます。

- **`nvwabase fact "confirmed observation"`** — 外部メモリ：AI のセッションは死んでも、グラフは
  生き残り、後継者がグラフを読んで引き継ぎます。
- **`nvwabase intent --from f001 "what to do"`** — 作業の単位：既存の事実から提案される新しい
  インテント。
- **`nvwabase dispatch reason`** — コマンダーが提案し / 実行者が作業し / 検証者がチェックする。
  あらゆる結論はグラフへと書き戻されます。

シェルコマンドを実行できるエージェントなら（Claude Code / Codex / Gemini / 自作スクリプト）どれでも、
`nvwabase` CLI を通じて同じグラフを読み書きできます — **基盤はエージェントを選ばず、エージェントは
シナリオを選ばない。** [nvwabase の README](https://github.com/N1nEmAn/nvwabase) を参照してください。

## 3. 基盤から軍団へ：18 のバージョン

Tencent の v1bench トレーニンググラウンドで 18 のバージョンをイテレーションしました。

```
ドライバー時代（固定スクリプトが AI ペインを操縦する）
  → 瘢痕組織：クォータ切れで死んだときの自動キーローテーション / コンテキストが飽和した
    ソルジャーの自動入れ替え / コマンダーが自分自身に引き継ぎ文書を書き、自らの後継者として
    再開する
  → 精鋭タスクフォース（ロールが自ら育った）：
    スカウト（4 分で標的の難易度を偵察） → ソルジャー（物量）かジェネラル（難関への強襲 +
    自前の分隊を雇う）かを決める
  → 創発：シグナルマン、業績評価、受け継がれる教訓 ...（§5）
```

## 4. アーキテクチャ：基盤の上の六つの制度

<p align="center"><img src="docs/assets/six-institutions.jpg" alt="六つの制度と三ウィンドウのランタイム" width="720"></p>

最初の三つは女媧ファウンデーション（創造 / 言語 / 歴史）であり、
次の三つはイテレーションから育った制度です。

- **法** — コマンダーのドクトリン（易しいものを優先する並列スケジューリング、
  ボトルネック時に半分解けた標的を救い上げる、損切りの規律）。
  そのすべては [docker/commander/SKILL.md](docker/commander/SKILL.md)
  （426 行、競技当時のオリジナル）に。
- **経済** — モデルの階層化：コマンダーとジェネラルは GLM-5.3 を、ソルジャー
  とスカウトは DeepSeek V4.1 Flash を動かす。精鋭の頭脳が判断し、軽量の頭脳が
  物量を生み出す — これが 10 億トークンで 45 億トークンを打ち負かした方法です。
- **分業** — コマンダー / ジェネラル / スカウト / ソルジャー、そして
  **自ら発明したシグナルマン**。

ランタイムにはウィンドウが三つしかありません。**コマンダー**（盤面を読む →
判断する → 指令を出す。自分で攻撃を実行することは決してない）、**AI 軍団**
（tmux ペイン内のジェネラルとソルジャー）、そして**ウォッチドッグ**（純粋な
スクリプト：クラッシュしたコマンダーを `--continue` で再起動し、キーをローテーション
し、終了のブザーで片付ける — 戦略ゼロ、生存維持のみ）です。

## 5. 成果と創発

<p align="center"><img src="docs/assets/token-comparison.jpg" alt="トークン比較：10 億 vs 2位の 45 億" width="720"></p>

| チーム | スコア | フラグ | トークン |
|---|---|---|---|
| **sapper-v2（私たち）** | **80.18** | 85 | **10 億** |
| 2位 | 79.29 | 85 | 45 億 |
| その他トップ 10 チーム | — | — | 15〜45 億 |

**それが自ら発明したもの**（事前にコード化された振る舞いはゼロ行）：

- **シグナルマン**：ソルジャーがフラグの提出を何度も失敗した末に、コマンダーは
  すべての提出を停止し、未提出のフラグを集めて一箇所でまとめて得点化する専任の
  新しいロールを創り出しました。
- **業績評価**：1 時間成果を出せなかったソルジャーに対し、はっきりと言葉で、
  何か新しいものを出すか、さもなくば停止されるかだと告げる。
- **全部大文字のルール**：正しいツールの使い方を全部大文字で強制する — 職場の
  規範が生まれ、広まり、守られていく。
- **ローテーションと受け継がれる教訓**：コンテキストが飽和した（実測で約 260K
  トークン）ソルジャーはリサイクルされ、次のソルジャーのために書き残された
  プレイブックを残していく。
- **戦術的な発明**：チャレンジの系統をまるごと一掃した再利用可能なシェルコード
  テンプレート、全自動のピボットパイプライン、後継 AI のための取扱説明書。
- **同型転移**：コマンダーがすべてのチャレンジを読み、構造的に同一の系統を見抜き、
  実証済みのプレイブックを新しい新兵のミッションへと蒸留する — 終盤のペースは
  **3 分で 1 問**に達しました。

多段階の深掘りチェーン（ある業界レポートはその成功率を 29.5% としています）は、
系統まるごと攻略されました。完全なタイムラインは
[BATTLE-REPORT.md](BATTLE-REPORT.md) に。

## 7. 安全性と責任：タガント提案

過去のシーズンで生まれた優れた攻撃ツールは、悪用されてきました。かつてスクリプトキディが
与えられる被害には限界がありましたが、AI があれば、同じオープンソースツールが悪意ある者の手に渡った
とき、その被害は桁違いに拡大します — **大いなる力には大いなる責任が伴う**のです。

私たちは**タガント（taggant）**メカニズムを提案します。これはオープンソースの攻撃ハーネスに強く
結合されたマーキングで、認可されたテスト中は無害ですが（合法的な作業中に自分の IP やユーザー名が漏れても
誰も気にしません）、違法な侵入の際には情報が**被害者**へと漏れ、帰属の特定を支えます。敵対的な前提
（専門家による除去、濡れ衣）に対応するには暗号学的な設計が必要であり、それにはコミュニティでの共同
構築が欠かせません — 私たち自身の能力には限りがあるので、ぜひ参加してください。将来のリリースに
含めることを試みるかもしれません。
